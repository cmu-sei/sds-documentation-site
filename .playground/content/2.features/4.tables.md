Use this page to learn Markdown table syntax, alignment options, and practical patterns you can reuse in your documentation.

## What are tables?

Tables organize repeated data into rows and columns so readers can quickly compare values. They work well for feature matrices, support references, settings, and status summaries. All rendered tables on this page are sortable. Click any column header to sort by that column.


## Why use tables?

Tables help:

- **Increase scanability** for structured information.
- **Speed up comparisons** across options, versions, and statuses.
- **Standardize presentation** for repeated fields and values.

## Markdown Format

::code-block{title="Basic table syntax"}
```markdown
| Feature | Description | Default |
| --- | --- | --- |
| Search | Full-text content search | ✅ Enabled |
| Dark mode | Theme switching support | ✅ Enabled |
| Table of contents | Auto-generated from headings | ✅ Enabled |
```

## Alignment

You can align content per column using colons in the separator row.

::code-block{title="Column alignment"}
```markdown
| Left | Center | Right |
| :--- | :---: | ---: |
| Name | Status | Score |
| Lume | ✅ Active  | 92 |
| ScribeAI | 🧪 Beta  | 88 |
```

## Tips for effective tables

- Keep column headers short and specific.
- Avoid putting long paragraphs inside cells.
- Use consistent value formats (for example, `Yes/No` or `Enabled/Disabled`).
- Use emojis sparingly as visual cues (for example, `✅` for pass, `⚠️` for caution).
- Prefer multiple small tables over one very wide table.
- Add context in nearby text so readers understand what the table represents.

## When not to use a table

A table is usually not the best format when:

- The content is mostly narrative prose.
- You only have one or two data points.
- The layout would require too many wrapped lines per cell.

In those cases, consider a list, callout, or short paragraph instead.
